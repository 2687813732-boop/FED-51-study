# FDE 51 学习助手

按你那份《FDE 入门 51 天学习计划（11月11日–12月31日）》做的安卓 App。
打开就是今天该干什么，做完提交，它给你打分、写总结、告诉你明天第一件事。

---

## 一、装到手机上

1. 把 `FDE51学习助手.apk` 传到手机（微信文件传输 / 数据线 / 网盘都行）。
2. 点开安装包，系统提示「未知来源」时允许一次。
3. 装好后打开 App，第一次会问通知权限 —— **点允许**，不然到点它喊不了你。

支持 Android 6.0 及以上（minSdk 23，targetSdk 35）。

### 装完建议做两件事

- **允许通知**：设置 → 应用 → FDE 51 → 通知，全部打开。
- **关掉电池优化**：设置 → 应用 → FDE 51 → 电池 → 不受限制。
  小米/红米、华为、OPPO、vivo、三星这类系统杀后台比较狠，不加白名单的话提醒可能被延后。

App 里「我的 → 每日提醒」可以看通知权限状态，也可以发一条 3 秒后的测试通知，确认能不能响。

---

## 二、它每天怎么管你

### 今日

- 日期自动对上计划里的第几天（11/11 = D1，12/31 = D51）。
- 四个时间块照原计划排：09:00–11:00 学概念、11:10–13:10 跟练、14:30–16:30 独立做、16:40–18:40 产出复盘。
- 每块都写了「学什么 / 动手做什么 / 当天产出」，勾一下就记一次完成。
- 点时间块可以进专注计时，开始 / 暂停 / 完成，时长会算进当天投入。
- 交付动作三件：代码提交、产出链接、写笔记。做完勾上，跟提交表单一回事。

### 提交

一天结束点「提交今日」，填三段：学会了什么、卡在哪、明天第一件事，再贴个链接、填投入时长。
提交后立刻出评价：

| 项目 | 分值 |
| --- | --- |
| 四个时间块完成度 | 40（每块 10） |
| 三项交付动作 | 10 |
| 学习笔记（≥15 字） | 20 |
| 产出链接 | 15 |
| 准时（22:30 前提交） | 15 |

90+ 是 S 优秀，80+ A 过关，70+ B 及格，60+ C 勉强，60 以下 D 欠账。
评价里除了分数，还有一句总结、三条做得好的、一条明天改一点，以及明天第一件事。

### 计划

8 周折起来看，51 天全在里面。点任意一天看详情；漏了的那天可以补卡，补的记录会标出来。

### 复盘

周日晚上那 30 分钟：四问复盘 + 6 项验收清单（少于 4 项不算过）+ 本周打卡天数 / 专注时长 / 平均分自动汇总。写完保存成周报。

### 我的

热力日历（51 格，颜色深浅是当天得分）、连续打卡、完成率、问题池、导出 / 导入数据、通知开关、重置。

## 四、数据存在哪

全部存在手机本地（WebView 的 localStorage），不联网、不上传、没有账号。

换手机或者怕丢：**我的 → 导出数据**，会生成一份 JSON，存到手机里；新机装好后用「导入数据」读回来。

卸载 App 会连数据一起删掉，卸载前先导出。

## 五、开发说明

- 壳：Capacitor 7 + 原生 WebView；通知用 `@capacitor/local-notifications` 的本地定时通知（不走推送服务器，离线也能响）。
- 前端：原生 JS，无框架；`www/app.js` 一个文件管全部逻辑，`www/data.js` 是从 docx 解析出来的 51 天数据。
- 数据来源：`tools/extract_plan.py` 解析原 docx 的表格 6–13，生成 `www/data.js`。计划改了重跑一次即可。
- 构建环境：Node 24、JDK 21、Android SDK 35（platforms;android-35 + build-tools;35.0.0）。Capacitor 7 的库要求 Java 21，用 17 会报「无效的源发行版：21」。

```bash
npm install
npx cap copy android
cd android
gradlew.bat assembleDebug     # 调试包
gradlew.bat assembleRelease   # 正式签名包（产物在 app/build/outputs/apk/release/）
```

> 签名用的 keystore 在 `android/fde51-release.jks`，别名 `fde51`，密码 `fde51study`。
> 它和 `android/key.properties` 都写在 `.gitignore` 里，**不进仓库**。新克隆下来要发正式包，
> 先放好这两个文件，Gradle 会自己读 `key.properties`；没有它 `assembleRelease` 会出未签名包。
> 这两个文件丢一个，以后就没法覆盖升级了。

> 兼容性说明：Capacitor 7 的库要求 Java 21。构建前把 `JAVA_HOME` 指到 JDK 21
> （本机是 `C:\Users\26878\jdk21\jdk-21.0.5+11`），否则 Gradle 会报「无效的源发行版：21」。

### 目录

```
fde51-app/
├─ www/                 前端（index.html / app.js / styles.css / data.js / icons / manifest）
├─ tools/               docx 解析、图标生成、浏览器自测脚本
├─ assets/              Android 图标与启动图源文件
├─ android/             Capacitor 生成的安卓工程
├─ capacitor.config.json
└─ package.json
```

### 网页版

`www/` 本身就能跑：用浏览器打开 `www/index.html` 即可（手机上「添加到主屏幕」也能当 PWA 用）。
网页版的提醒靠浏览器通知，得页面开着；要真正到点响，还是装 APK。

## 六、已知限制

- APK 用的是项目自带的正式签名（不是 debug 签名），可以直接装；以后要发新版，用同一个 keystore 签才能覆盖升级。
- 四个提醒每天固定时间，不区分工作日和周末（计划本来就是 51 天连轴）。
- 计划结束后（12/31 之后）提醒还会响，可以在「我的」里关掉。
- 没有云同步，多设备之间靠导出 / 导入 JSON。
- 评分是本地规则算的，不是 AI 模型；想更细的点评可以看评价里的建议和明天预告。
